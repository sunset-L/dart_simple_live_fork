# Simple Live Web

网页客户端，参考 Windows 客户端的左侧导航、平台标签、直播网格和设置列表。包含首页、关注、分类、我的、账号管理、数据同步、历史记录、屏蔽词管理和独立标签页播放器。后端继续使用 Dart，共享客户端平台解析与弹幕协议。

## Windows 双击启动

使用 Windows 10/11 x64，从完整仓库中的 `simple_live_web` 目录双击 **`start.bat`**：

- 自动检查 Node.js、完整 Dart SDK、Git、项目锁文件及随项目提供的 QuickJS DLL。必须同时保留相邻的 `simple_live_core` 和其中的 `packages/tars_dart`，不能只复制网页目录。
- 首次缺少工具或需要初始化/更新项目依赖时，先显示安装清单、用途、下载来源、存放位置和手动替代方案。**按 Enter 才开始准备，输入其他内容则取消**；不会自动接受安装。
- 优先复用已有工具。缺少时下载下表中的 Windows x64 便携版到 `.runtime`，校验固定 SHA-256 后解压，不写系统 PATH、注册表或全局安装目录；下载显示进度，解压和依赖安装显示阶段及命令输出。
- npm 依赖使用 `npm ci --progress=true --no-audit --no-fund`；Dart 使用 `dart pub get --enforce-lockfile`，保留已提交的版本和 Git 提交号，不执行升级或原生 C++ 构建。首次通过启动器准备一次后，后续根据工具版本、锁文件和缓存是否有效决定是否重新准备，不是每次都获取依赖。
- 前后端均准备就绪后，窗口打印**实际网页访问地址**、API 地址和本机数据目录。默认网页端口 23236、API 23238；占用时向后选择空闲端口，网页与 API 不共用端口，也不会停止其他会话的服务。以窗口输出为准，不把 API 地址当作网页入口。
- 所有进程都属于本次窗口的 Windows Job Object。**关闭窗口或按 Ctrl+C 会关闭本次前端、Dart 后端及子进程**；准备过程中关闭窗口，也不会留下安装命令继续运行。任一服务异常退出时，启动器退出并清理本次服务，保留错误提示等待按键。
- 无目录写权限、工具被系统策略拦截、下载失败或解压失败时，窗口提示手动处理后重新打开 `start.bat`；不自动提权，也不要求安装庞大的构建工具链。
- 始终以 Vite 开发模式启动，不执行网页 `build` 或 Android 打包。前端热更新，修改 Dart 后端后关闭窗口再双击启动。

脚本内固定的自动下载版本及来源如下；已有兼容工具不强制替换成这些版本：

| 工具 | 自动下载版本 | 用途与来源 |
| --- | --- | --- |
| Node.js，含 npm | 24.22.3 x64 | Vite/React 开发服务和 npm 依赖；`nodejs.org/dist` 官方 ZIP |
| 完整 Dart SDK | 3.13.1 x64 | 本地 API、同步和平台解析；`storage.googleapis.com/dart-archive` 官方 ZIP |
| MinGit | 2.56.1 x64 | 仅用于获取 Dart 的 Git 依赖；`github.com/git-for-windows/git` 官方发布 ZIP |
| QuickJS DLL | 随仓库提供 | 斗鱼/抖音签名，位于 `native/windows-x64`，不另行下载安装 |

**没有额外浏览器插件需要安装**。Node、Dart、Git 是开发工具，不是浏览器插件。也不安装 Flutter、Visual Studio 生成工具、Visual Studio Installer、Windows SDK、Windows SDK AddOn、编辑器字体或额外 VC++ 运行库。Windows PowerShell 5.1 和 .NET 使用系统自带版本；进程清理由 `kernel32.dll` 完成。

### 手动准备

若公司策略禁止脚本、没有目录权限或希望自行管理工具，可手动安装：

- [Node.js 官方下载](https://nodejs.org/en/download)：64 位 Node.js 22.12+，推荐 24 LTS，并保留自带 npm。安装器中的额外编译工具/Chocolatey 选项不需要勾选。
- [Dart SDK 官方归档](https://dart.dev/get-dart/archive)：完整 SDK 3.13+，推荐 3.13.1。锁文件要求 3.13+，只安装 Dart 3.10 无法满足当前依赖。已有 Flutter 3.47.1 包含可用 SDK，但开发网页不需要专门安装 Flutter。
- [Git for Windows](https://git-scm.com/download/win)：常规安装版或 MinGit 均可，用于 `pub get` 获取已锁定的 Git 依赖。

常规安装后重新打开窗口，让 PATH 生效；独立 Dart 可以用 `DART_EXECUTABLE` 指定。也可以从启动脚本显示的官方 URL 用浏览器下载并解压为以下结构，保留 ZIP 内的许可证及运行文件：

```text
simple_live_web/
  start.bat
  .runtime/                         本机缓存，不提交 Git
    node/node.exe                   Node ZIP 内层目录的内容
    node/node_modules/npm/
    dart-sdk/bin/dart.exe            Dart ZIP 内的 dart-sdk
    git/cmd/git.exe                 MinGit ZIP 的内容
    pub-cache/                      默认 Dart 包缓存
    downloads/                      已校验的下载包
    dependencies.json               启动器依赖准备记录
```

只把完整仓库放在个人可写目录即可，不需要管理员权限。不要关闭系统安全策略；策略不允许 PowerShell 时请使用下方的手动双终端启动方式。安装失败可重新运行：已成功准备的工具会复用，下载不完整或校验失败的文件不会执行。旧便携工具被替换时保留为 `.runtime/previous-*`，不会删除系统中的工具。

### 配置

启动器继承启动窗口的环境变量，不需要把配置写进 BAT。默认不创建包含密码的配置文件，WebDAV 地址及密码在页面内配置并保存到本机设置。

| 环境变量 | 默认/作用 |
| --- | --- |
| `SIMPLE_LIVE_WEB_PORT` | 双击启动的网页优先端口，默认 23236；占用时自动找空闲端口 |
| `PORT` | API 优先端口，双击启动默认 23238；手动 `npm run server` 默认 23236 |
| `DART_EXECUTABLE` | 完整 SDK 的 `dart.exe` 路径；其次查找项目便携版、仓库已有 FVM SDK、PATH |
| `SIMPLE_LIVE_DATA_DIR` | 可选的本机数据目录；不设置时 Windows 使用 `%APPDATA%\simple-live-web` |
| `PUB_CACHE` | 启动器未指定时使用 `.runtime/pub-cache`；显式指定时沿用指定目录 |
| `PUB_HOSTED_URL`、npm 自有配置 | 保留已有包源/网络配置，不自动修改；使用可信源 |
| `SIMPLE_LIVE_SERVE_STATIC` | 双击启动固定为 `0`，不提供可能过期的 `dist` 网页 |

例如在命令提示符中临时指定端口和数据目录：

```bat
set "SIMPLE_LIVE_WEB_PORT=23336"
set "PORT=23338"
set "DART_EXECUTABLE=D:\tools\dart-sdk\bin\dart.exe"
set "SIMPLE_LIVE_DATA_DIR=D:\SimpleLiveData"
call start.bat
```

只读检查环境、不安装或启动服务：

```bat
start.bat -CheckOnly
```

本次启动器运行只修改本机缓存和生成文件，不把账号、Cookie 或 WebDAV 密码写入启动脚本。`.runtime`、`.dart_tool`、`node_modules`、`dist` 和日志不提交；个人数据保存在配置的数据目录，不随端口或工具缓存改变。

## 手动双终端运行

需要 Node.js 22.12+（推荐 24 LTS）、完整 Dart SDK **3.13+** 和 Git。Windows x64 网页开发不需要 Visual Studio 或 Windows SDK。以下命令适用于已自行安装工具的环境；依赖未变且已经准备好时无需重复获取：

```sh
npm ci
dart pub get --enforce-lockfile
```

在 Windows 的第一个命令提示符中启动 API：

```bat
set "PORT=23238"
set "SIMPLE_LIVE_SERVE_STATIC=0"
npm run server
```

在第二个命令提示符中启动网页，`PORT` 必须与 API 一致：

```bat
set "PORT=23238"
npm run dev -- --port 23236 --strictPort
```

打开 `http://127.0.0.1:23236`；`/api` 和 `/ws` 转发到本机 Dart 服务。PowerShell 中设置环境变量使用 `$env:PORT='23238'`，其他系统按对应 shell 设置即可。Vite 不指定前端端口时默认 5173，手动服务不指定 `PORT` 时 API 默认 23236。手动模式由各终端独立负责进程，不等同于 BAT 的整组清理；Windows 推荐用 `start.bat`。

开发时无需执行 `npm run build`，前端修改由 Vite 热更新。Dart 服务默认只提供 API，不会因为目录里残留 `dist` 就提供旧网页。

`scripts/serve.mjs` 优先使用 `DART_EXECUTABLE` 指定的 Dart 可执行文件，其次使用仓库 `.task-cache/fvm/versions/3.47.1` 内的 SDK，最后查找 PATH 中的 `dart`。`PORT` 可修改监听端口。服务仅绑定本机 IPv4，不应直接部署到公网或解除来源校验。

若更改 API 端口，为两个终端设置相同的 `PORT` 环境变量。前端开发端口可用 `npm run dev -- --port 23237` 指定；升级旧版时可先复用原网页端口，以便自动迁移该地址下的旧浏览器数据。

关注、标签、历史和屏蔽词保存在本机 Dart 服务的固定数据目录，不随前端或 API 端口改变；`localhost`、`127.0.0.1`、开发模式和正式模式也共用这一份数据。Windows 默认目录为 `%APPDATA%/simple-live-web/library.json`；其他系统使用 `$XDG_DATA_HOME/simple-live-web` 或 `$HOME/.local/share/simple-live-web`。可通过 `SIMPLE_LIVE_DATA_DIR` 指定目录，同一份数据的各个服务必须使用相同目录。

主题模式、主题色、侧栏收起状态和弹幕设置保存在同目录的 `preferences.json`，同样跨端口共用。旧浏览器设置在原地址首次打开新版时迁移，只填补尚未保存的字段，不覆盖已有本机设置；新地址不会把默认值写入并覆盖旧设置。关注与设置只在页面打开或手动刷新时读取，不轮询、不订阅服务端变更，保存失败会提示。

开发模式有两个服务：Vite 提供最新源码页面，Dart 提供 API。通常网页为 `http://127.0.0.1:23236`、API 为 23238；启动器遇到端口占用时可能选择其他端口，以启动窗口输出为准。不要把 API 后端端口当作网页入口；前端端口改变仍共用本机数据。

只在用户明确要求正式构建或部署时运行 `npm run build`。如需由 Dart 提供正式静态页面，须显式设置 `SIMPLE_LIVE_SERVE_STATIC=1`，开发时不启用。

## 核心库与原生依赖

直播列表、搜索和分类使用相对路径依赖 `../simple_live_core`，不复制平台解析逻辑。React + TypeScript + Ant Design 负责浏览器界面，本地 Dart 服务处理跨域接口请求。

Windows x64 默认加载随项目提交的 `native/windows-x64/dart_quickjs.dll`。这个约 1.2 MB 的运行库只依赖 Windows 自带的 `KERNEL32.dll`，无需 Visual Studio、Windows SDK 或额外 VC++ 运行库。`scripts/serve.mjs` 校验文件完整性和依赖源码版本，用 Dart SDK 自带的 kernel 编译器生成后端程序，显式登记 DLL，再直接运行；不触发 C++ 编译，不负责安装系统工具。`start.bat` 仅在确认后补齐缺少的便携工具和项目依赖。修改后端代码后重启即可，清空启动缓存也会重新生成，DLL 不在缓存目录中。

换到另一台 Windows x64 电脑时，保留此目录、许可证及依赖锁文件，准备已有的 Node.js、完整 Dart SDK 和 Git，执行上述依赖获取与启动命令即可。`DART_EXECUTABLE` 可指向独立 Dart SDK 的 `dart.exe`，无需另外安装 Flutter 来开发网页。具体来源、版本与更新规则见 `native/windows-x64/README.md`。更新 QuickJS 依赖时必须同步提供配套 DLL，版本不匹配会明确报错；需要安装新工具时先征求用户同意。

这只改变 Windows 网页后端的启动，不修改 core、Android 或其他 Flutter 客户端。Linux/macOS 仍使用 `dart run` 及对应 C 工具链，Windows ARM64 暂未提供专用运行库。不要绕过启动脚本直接执行 `dart run bin/server.dart`，那仍会进入上游原生编译流程。

`npm run server:native` 是默认完整模式的别名。需要明确停用原生功能时可以使用降级模式：

```sh
npm run server:lite
```

降级模式直接运行 Dart VM，支持同步功能及不依赖 QuickJS 的平台接口，**不支持斗鱼和抖音播放、抖音推荐列表及分类下直播列表**。完整模式启动时先初始化 QuickJS，加载失败则停止服务，不会静默降级。健康检查不代表所有平台真实直播验收通过，平台接口仍受网络、反爬策略和核心库实现影响。

## 播放页

- 从直播列表、关注、历史进入独立播放标签页；同一页面重复点击同一房间会聚焦已有标签页，不重复加载。
- 直播间网页地址统一为 `/live/{平台}/{房间号}`，旧 `/playback/...` 地址自动转换并保留查询参数与锚点；取流接口仍使用 `/api/playback/...`。
- 使用 ArtPlayer（查询时 GitHub 约 4.2k stars）、hls.js（约 17k stars）、flv.js（约 23k stars）与 ArtPlayer 弹幕插件。HLS、FLV 引擎按需加载。
- 支持哔哩哔哩、斗鱼、虎牙、抖音；视频底部工具栏提供线路、清晰度、刷新取流、播放暂停、音量静音、系统全屏、网页全屏及原生画中画。刷新在左侧，音量在右侧画质选项之后、画中画之前；线路和画质菜单悬停展开，点击选项切换。画面比例和播放信息仅放在右键菜单，不再提供控制锁定。
- 抖音沿用 App 的 core 访客流程：未设置个人 Cookie 时使用 core 内置的默认 `ttwid`，房间取流和弹幕签名使用现有 QuickJS 运行库。不要求登录或手动输入 Cookie，不新增浏览器插件；HLS/FLV 线路共用现有播放器，需要请求头的线路通过 Dart 代理。默认访客标识的可用性、平台风控和画质仍取决于上游，不保证所有房间始终可播放。
- 无必要请求头时优先直连，失败自动改用 Dart 代理；随后尝试其他线路，保留可恢复的上一线路，全部失败后最多自动刷新两次。换源播放成功后校正选择状态。已知过期地址会提前刷新。
- Dart WebSocket 中继平台弹幕，提供断线重连、聊天列表、B站实时 SC、弹幕开关、透明度、字号、粗细、速度、区域、福袋过滤和屏蔽词。
- 屏蔽词与客户端同步；`/表达式/` 使用线性时间 RE2 引擎，避免复杂表达式冻结主线程。反向引用、前后查找等 RE2 不支持的规则不会生效，原规则仍保留在同步数据中。
- 关注和首次播放历史保存到本地服务；其他标签页及不同端口页面手动刷新后读取同一份数据。取关在首页、关注、历史和直播间均需要确认，添加关注无需确认。视频下方不再放功能或状态栏，播放状态位于关注图标旁边；分享菜单可复制直播间链接和播放链接，诊断入口已移除。右键菜单提供分辨率、帧数和缓冲等播放信息。
- 关注页与播放页的关注侧栏显示直播中、未开播或查询失败；首次进入读取一次，之后手动刷新，不定时刷新或切回页面自动刷新。服务端缓存状态 30 秒，不把查询失败当作未开播。
- 首页、关注和历史共用封面卡片：头像与主播名叠在封面下缘，火焰图标显示热度，标题放在封面下方。关注与历史显示平台图标与名称，首页及分类已有平台筛选，不重复展示平台。整张卡片进入直播间，已确认未开播的卡片禁止进入，关注及标签按钮仍可独立操作；关注列表按全部、直播中、未开播筛选，全部列表的直播中主播优先，同组保持原关注顺序，不展示房间号。
- 新关注先保存，再补齐头像；已有空头像在关注页查询资料后自动保存。卡片资料缓存 10 分钟，首页头像按可见区域加载并限制并发；哔哩哔哩直接读取公共房间信息，不请求弹幕凭据。未取得头像或图片加载失败时不显示默认图标占位。桌面侧栏中部边缘悬停显示收起和展开箭头，键盘聚焦时保持可见，收起后保留图标导航。
- 卡片统一网格与固定封面比例，切换筛选不因滚动条或图片尺寸改变卡片大小，桌面悬停时封面轻微放大。手动刷新保留旋转动画，结束后提示成功、失败或部分失败；没有自定义标签时隐藏标签栏。从关注进入历史时保留关注导航高亮与返回入口。
- 按钮、平台标签、关注筛选、弹窗、操作提示、同步表单及弹幕设置使用 Ant Design。右上角主题菜单支持浅色、深色、跟随系统、六种预设色和自定义颜色；主题统一由 `ConfigProvider` 的 `colorPrimary` 及明暗算法生成，并将设计令牌同步给布局样式。旧版外观选择会自动迁移，本机数据目录保存外观设置，播放页使用相同主题色及深色算法。
- 直播间视频与弹幕区紧凑并排，顶部独立标题栏已移除。视频上方第一行显示房间标题，第二行显示主播名、火焰热度和带图标的平台，热度过万显示“万”，过亿显示“亿”；小屏改为上下排列。页面和弹幕列表使用深色细滚动条。直播信息和缓冲共用播放器加载动画，单击画面不暂停，双击与 F 键只切换网页全屏，系统全屏从播放器图标进入，Esc 退出网页全屏；网页全屏不放大工具栏图标，并禁用底层页面滚动，缩小窗口也不显示页面滚动条，退出后恢复。关注图标立即同步本地数据并识别房间别名；聊天显示“用户名: 内容”，正文和滚动弹幕保留平台原色。
- 工具栏右侧统一显示弹幕开关与“弹幕设置”，沿用插件原有图标，普通和网页全屏模式保持一致，不再重复显示插件自带控件。弹幕设置和右侧设置页共用组件，提供显示开关、防重叠、福袋过滤、不透明度、字号、粗细、滚动时长和显示区域；颜色和上下边距配置已移除，旧设置不再生效。菜单挂在播放器容器内，全屏时仍可使用。控件通过 ArtPlayer 的挂载回调登记和清理，避免开发模式重复注册；初始化异常显示原因与重载入口，不让页面直接白屏。
- 桌面左右区域撑满页面可用高度，左侧播放器外层填满主播信息下方容器，视频等比居中，工具栏位于满高容器底部，右侧聊天和设置独立滚动；小屏上下分配可用高度。滚动弹幕位于左侧满高容器，显示区域与滚动轨迹按弹幕层尺寸计算；网页全屏和系统全屏时切入全屏容器，退出后恢复，不影响视频控制操作。工具栏失焦或停止操作 3 秒后隐藏，悬停工具栏、键盘操作和打开设置菜单时保持显示。
- 点击播放页主播头像，在当前标签页返回关注页；直接打开的直播间同样可用，不依赖浏览器历史。
- 代理只接收服务端登记的上游地址，限制并发和清单大小，对实际连接 IP 做公网校验，跨主机跳转去除认证头。不要向不信任的人分享带签名的播放直链。

### 当前边界

- 按约定不做移动端触摸手势。定时关闭、系统亮度与方向控制、原生悬浮窗、录制和投屏未移植。
- 账号授权用于平台取流，不提供发弹幕入口，也无法保证平台专享画质；SC 仅展示当前连接收到的消息，不拉取历史。
- FLV、HEVC 解码取决于浏览器与系统，建议桌面 Chrome/Edge。取流完成后立即尝试有声自动播放，被浏览器拒绝时尝试静音自动播放；仅当静音播放也被拦截时需要手动播放。原生画中画只显示视频，不包含网页弹幕。
- 抖音顶部热度使用房间详情的 `room_view_stats.display_value`，不使用弹幕协议的 `totalUser` 覆盖不同统计口径；点击热度单独请求最新详情，不重载播放器。请求期间火焰图标显示加载动画，失败保留原值并提示。
- 通用主播卡片与直播间顶部的热度图标、数字悬停时显示带千分位逗号的完整数字，不使用“万”或“亿”简写；页面上的紧凑显示保持不变。
- 直播页右侧区域沿用首页侧栏的悬停箭头，收起后完全隐藏且不占空间；悬停页面右边缘可展开，键盘聚焦也显示按钮。首页与直播页按钮悬停时保持原底色，只改变箭头颜色。收起状态保存在本机设置中，不影响视频播放或滚动弹幕，网页全屏时隐藏该按钮。
- 右栏收起时卸载标签栏、弹幕列表及其他面板，仅保留空容器，不再创建列表 DOM、执行列表筛选或更新滚动位置；关注状态查询也暂停。弹幕连接和最多 300 条内存缓存继续保留供画面滚动弹幕使用，展开后恢复当前面板并显示最新缓存。
- 弹幕滚动时长范围为插件支持的 1–10 秒；播放器设置保存在本机数据目录，不属于客户端备份同步范围。
- 服务仅监听本机，当前不是供局域网手机直接访问的部署方案。

## 数据同步

- **账号管理**：从“我的”进入。哔哩哔哩支持二维码登录、粘贴 Cookie、用户名和失效检查；斗鱼只保存 `dy_auth`，校验沿用核心库的在播取流判据，网络失败不清除授权。抖音默认使用核心库访客凭据，也可保存自定义 `ttwid`；虎牙无需登录。
- 账号凭据保存在与关注数据相同的本机数据目录 `accounts.json` 中，使用版本检查、文件锁和临时文件替换，不写入浏览器存储。账号列表接口只返回状态；仅显式账号备份操作读取凭据。扫码状态只在登录窗口打开期间查询，关闭或过期后停止；账号列表没有后台轮询或服务端变更通知，其他页面更新后需手动刷新。
- **WebDAV**：检查连接、上传和恢复，路径与客户端一致，为 `<WebDAV 根路径>/simple_live_app/backup.zip`。根地址不要重复填写 `simple_live_app`。
- **本地 ZIP**：导入和导出客户端兼容备份，可离线使用。
- **局域网**：手动填写运行中客户端的 IPv4 地址，通过其 23234 端口检查连接和推送。现有客户端协议只有写入接口，没有读取接口，因此此处不提供拉取或自动设备发现；客户端数据进入网页使用 WebDAV 或 ZIP。
- 同步范围：关注与标签（同时处理）、历史记录、弹幕屏蔽词，以及默认关闭的账号选项。账号导出、云端上传、恢复或设备推送均需额外确认敏感信息风险。普通列表默认合并，覆盖需要确认；云端上传以本地所选数据替换对应文件。
- 哔哩哔哩账号文件为 `SimpleLive_bilibili_account.json`，数据为 `{data:{cookie}}`；斗鱼为 `SimpleLive_douyu_account.json`，数据为 `{data:{auth}}`，与 App 的 ZIP/WebDAV 和 `/sync/account/bilibili`、`/sync/account/douyu` 局域网协议兼容。网页仅保存斗鱼 `dy_auth`，不备份其他斗鱼 Cookie 字段。
- 抖音 `ttwid` 使用网页扩展文件 `SimpleLive_douyin_account.json`，数据为 `{data:{cookie}}`，仅支持 ZIP/WebDAV；App 没有对应的抖音账号同步协议，不支持局域网推送此项。
- 历史合并保留相同 ID 中时间较新的记录。ZIP 支持仅包含账号文件的备份，所选列表和账号先解析并校验再写入；不合法备份不会清空本地数据。非空账号会替换原账号，合并模式保留已有账号不被空凭据清除，覆盖模式则允许清除。限制压缩包及解压内容为 20 MB。
- 列表与账号是独立文件，不能跨文件事务回滚；列表恢复成功但账号写入失败时明确提示部分成功，可只选择账号重试。局域网账号接口同样会替换或清除目标账号，与普通列表合并开关无关。
- WebDAV 上传先读现有备份，保留未选文件和 App 设置；未选账号文件原样保留。新建网页备份只有明确选中的账号才包含对应凭据。账号文件与 App 现有协议一样是明文，备份包含可复用的登录授权，不要分享，使用可信存储和设备。
- WebDAV 地址、用户名和密码与主题、播放器设置一起自动保存到本机 `preferences.json`，刷新页面或切换端口后保留；按字段合并更新，不覆盖其他页面的设置。密码在本地文件中为明文，不写入浏览器存储、备份 ZIP 或服务日志。推荐 HTTPS；HTTP 连接会额外警告。旧版仅在页面内存中的已丢失配置无法恢复，需重新填写一次。
- 服务提供强 ETag 时使用 `If-Match` 检测并发更新；新文件使用 `If-None-Match`。不提供强 ETag 的服务器需再次确认，无法保证多设备并发安全。
- 现有客户端的关注、标签等是独立写入接口，不能事务回滚。局域网部分成功时会明确提示已传输项目，需要重试完成剩余同步。

关注、标签、历史和屏蔽词通过 `/api/library` 写入固定的本地数据文件。保存成功后才更新界面；使用版本检查、跨进程文件锁和临时文件替换，避免多端口或多标签页互相覆盖。首次打开或手动刷新时读取，不定时查询或在切回页面时自动请求，也没有服务端变更通知。文件损坏时停止写入，保留原始数据导出和确认清除入口；连接失败时只提供重试。

首次访问新版时，自动合并当前浏览器来源下旧版 `localStorage` 数据，保留原始数据并记录迁移标记。浏览器不能直接读取其他端口的旧存储，因此已有旧关注的每个地址需要用新版访问一次；之后切换任意端口无需再次迁移。关注、账号、主题和播放器设置均保存到本机服务的数据目录，清除浏览器站点数据不会删除这些文件。
